## 티켓별

### KL-012 · 요청·캐시·실패 처리

| 구분 | 내용 |
|---|---|
| 확인된 문제 | **시세 갱신이 한 번 실패하면 홈 지수 카드 6개가 빈 상자**가 됨 — 간이 fetcher(`r.json()`)가 503 의 `{error}` 를 데이터로 받아 직전 값을 지움, 오류·마지막 확인 시각 표시 없음. 코인 시장환경·관심 코인 시세도 같은 구조 [확인됨: 실패 주입 테스트] · 초록 '실시간'이 남는 문제는 없었음(T01 의 그 부분은 이미 충족) |
| 수정 | 홈 지수 레일·코인 시장환경·코인 시세를 공용 `jsonFetcher`(실패 = 예외)로 → SWR 이 직전 값 유지 · 실패 중엔 카드 배지 '갱신 실패' + 위에 'HH:MM에 받은 값을 보여 주는 중(자동 재시도)' |
| 확인 | 실패 주입(첫 응답 뒤 503): 홈 값 12개·코인 18개 유지, '실시간' 0, '갱신 실패' 6·8개, 안내 문구 표시 [확인됨] |
| 남은 위험 | 같은 간이 fetcher 를 쓰는 파일이 58개 더 있음 — 잠금 화면처럼 401 본문으로 상태를 판단하는 곳이 있어 일괄 교체는 하지 않음(화면별로 옮길 것) · 소스별 sourceTime/cachedAt 필드 통일은 하지 않음 |

### KL-013 · 첫 데이터 속도

측정상 첫 데이터 0.45 s·LCP 0.4~0.56 s·CLS 0(빠른 회선 기준)이라 홈·캘린더를 서버 렌더로 바꿀 근거가 약하다고 판단 — **변경하지 않음**. 느린 회선(4G 제한) 측정과 공통 묶음 축소는 다음 과제.

### KL-014 · 글자 크기 부채

| 구분 | 내용 |
|---|---|
| 수정 | 의미 토큰 `text-cap`(11px)·`text-cap-pc`(폰 11 / PC 12px)을 Tailwind `@utility` 로 정의 — 예전 덮어쓰기 규칙이 실제로 만들던 크기와 같음 · `text-[8~10.5px]` **754곳 → 0곳**(111파일) · `tests/typography.test.ts` 가 다시 생기면 실패 |
| 시각 회귀 | 같은 빌드 2회 측정으로 잡음 0 확인 후, 치환 전후 12화면 × 폰·PC = 24개 화면의 보이는 글자 크기 분포 **변화 0** [확인됨] |
| 남은 위험 | 'sm: 에서 더 크게'를 의도한 4곳(계절성·재무 표)은 640~1023px 에서 의도대로 최대 1px 커짐(측정 안 한 폭) · 색·카드 토큰 별칭 정리(`--cp-*`·`nv-*` 등)는 하지 않음 |

### KL-015 · 복기·실험 신뢰도

| 구분 | 내용 |
|---|---|
| 확인 | 선행 테스트 화면은 이미 n<30 '결론 불가'·두 기준 따로·비용 미반영 명시 [확인됨] · 부족: 30건을 '결론 시점'처럼 표현, 신뢰구간 없음, 비용 후 성과 없음 |
| 수정(표시 전용) | `lib/paperStats`: 평균 R 95% 구간, 앱 표준 비용(테이커 0.06%·메이커 0.02%·시장가 슬리피지 0.05%)을 거래마다 R 단위로 뺀 '비용 후' 추정 · 화면에 두 줄 추가, 30건 = '첫 중간 점검' 문구 · BNF 카드 30회도 같은 문구 · 판정 규칙 파일(`paperJudge`) 손대지 않음 |
| 실제 값(확정 24건) | 비용 전 평균 +0.33R(95% −0.26 ~ +0.93) · **비용 후 +0.18R(−0.44 ~ +0.79)** — 둘 다 0 포함 = 우위 불명 · 비용이 거래당 약 0.15R |
| 남은 위험 | 표본 외(out-of-sample) 분리·기준선(전체 후보) 비교는 엔진 판정 30건이 모인 뒤 |
