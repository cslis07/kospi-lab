## 2. 미리 정한 기록 규칙(결과를 보고 바꾸지 않음)

- 분석 화면에서 엔진이 평가될 때, **분석 시세가 5분 안으로 신선**하고 Phase 2 입력(유동성·뉴스·연준·일정)을 받았거나 받기 실패가 확정된 뒤.
- **코인별 60분에 한 번**. 단 상태(거래 보류/후보 없음/대기/조건 충족)나 엔진 선택 쪽이 바뀌면 바로.
- 같은 분석 시세는 한 번만. **덧붙이기만 하고 고치지 않는다**(최초 등록값 고정). 500건 넘으면 오래된 것부터 뺀다.
- **모든 상태를 기록**한다 — 보류·후보 없음 때의 가격 후보도 판정해서 '엔진이 거른 효과'를 비교한다.
- 항목: 엔진 판(`v0.2-p2`), 가중치, 입력 해시(관측값·이벤트·후보 요약), 상태·배경·정렬·데이터 범위·그룹 점수·보류 사유, 롱·숏 후보(구간·진입·손절·목표·순손익비·트리거), 왕복 비용 bp.

## 3. 사후 판정 규칙

- 각 후보를 **진입 기준가 지정가**로 보고 Bitget 1시간봉으로 판정. **24시간 안 미도달이면 무효**(성적 제외).
- 목표는 **1차 목표**. 같은 봉에서 손절·목표가 둘 다 닿으면 **손절 먼저**. **72시간에 마감**(미결이면 그 시점 종가로 평가).
- **순R = R − 비용**(수수료 8 + 슬리피지 5 + 펀딩 bp ÷ 손절폭).
- 같은 코인·방향·진입·손절 후보가 24시간 안에 다시 기록되면 한 건으로 센다.
- 비교 3묶음: **엔진 선택(대기·조건 충족)** / **전체 가격 후보(기준선)** / **엔진이 거른 후보**.
- **판정 끝난 엔진 선택 30건 전에는 성과를 판단하지 않는다**는 문구를 화면에 고정. 평균 순R 이 음수면 '관망 우선 유지'를 표시(§7 Phase 3).

### 알려진 한계(화면에도 표시)
- 15분봉 진입 확인(트리거)을 1시간봉으로 재현할 수 없어 **'구간 도달 = 체결'** → 실제보다 체결이 많다.
- 기록은 **분석을 실행했을 때만** 생긴다(서버 주기 실행 없음 — Vercel Hobby CPU 예산·새 크론 금지). 표본 시점이 고르지 않다.
- BTC·ETH 후보는 같은 거시 사건을 공유해 완전한 독립 표본이 아니다.
- 1시간봉은 심볼당 최대 200봉 × 10쪽(약 83일)까지만 받는다 — 그보다 오래된 기록은 판정되지 않는다.

## 4. 추천 진입가 카드 — 비용 반영 손익비

각 쪽에 '비용 반영 손익비 x / y (수수료·슬리피지·펀딩 차감 — 위 손익비는 비용 전)' 줄을 붙였다. 값은 엔진 평가 결과(`rr1Net`·`rr2Net`)를 그대로 쓴다. 로컬 실측 예: ETH 숏 비용 전 1.3/3.4 → **비용 반영 0.99/2.77**, 롱 3.3/5.2 → 2.46/3.98.
