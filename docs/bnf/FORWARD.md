## 3. 후보 규칙 (둘 다 롱 전용·1포지션·1시간봉·전체 국면)

공통 규칙은 [STRATEGY.md](STRATEGY.md) §3·§4 와 같습니다.
- 진입 조건: 일봉 SMA25 이격도가 직전 365일의 10% 분위수 이하인 봉이 최근 4개 1시간봉 안에 있고, 종가가 직전 봉 고가를 넘으면 신호입니다.
- 체결: 신호 봉 다음 봉 시가 + 슬리피지로 진입합니다.
- 손절: 4시간봉 ATR14 × 1.5 (1.2% ~ 8%, 8% 초과면 건너뜀)
- 보유: 최대 72시간, 청산 뒤 24시간 대기
- 비용: 편도 수수료 0.05% + 슬리피지 0.02% (진입·청산 모두)
- 자금: 위험 0.5%, 증거금 상한 25%, 5x, 초기 1,000 USDT (후보마다 따로)

| 후보 | 목표 | 근거 |
|---|---|---|
| **A** | 1.8R (1차 규격 그대로) | 백테스트 1시간·전체 국면이 과거·개발·OOS 세 구간 모두 평균 R 양수였으나 기준(PF 1.2) 미달 |
| **B** | **1.0R** (그 외 A와 동일) | 진단(E3)에서 평균 MFE 가 1R 안팎이고 72h 만기 거래가 평균 이익이었음. 이 관찰에서 나온 변형이라 과거 데이터로 판정하지 않고 **선행 테스트로만** 봅니다 |

후보는 둘로 제한합니다. 많이 돌릴수록 우연히 통과하는 후보가 생기기 쉽기 때문입니다.

## 4. 판정 (청산 거래 30회가 쌓인 뒤 한 번)

[metrics.ts `verdict`](../../lib/bnf/metrics.ts) 와 같은 순서·기준을 씁니다.
- 30회 미만이면 '진행 중 (n/30)' 으로만 표시하고, 판정하지 않습니다.
- 30회가 되면 순서대로 확인합니다: PF < 1 또는 평균 R ≤ 0 → MTM 낙폭 > 10% → PF < 1.2.
- 개발 구간 일관성 항목은 A 에는 Bitget 백테스트 1시간·전체 국면의 전체 구간 결과를 넣고, B 에는 적용하지 않습니다(과거 판정 없음).
- 펀딩 항목은 적용하지 않습니다.
- 통과해도 '추가 검증 후보'일 뿐 실거래 적합 판정이 아닙니다. 진입가를 실제로 알려 줄지는 그때 사용자가 따로 정합니다.

## 5. 기록 규칙

- **결정적 재계산:** 실행할 때마다 시작 시각 이후의 확정 봉으로 처음부터 다시 계산합니다. 실행이 늦어져도(GitHub 예약 실행 지연) 결과는 같습니다.
- **청산 거래 변경 감시:** 이전 실행에서 기록된 청산 거래가 재계산에서 달라지거나 사라지면, 이전 값을 '기록 변경' 목록에 그대로 남기고 화면에 경고로 표시합니다(거래소 캔들 수정 등). 성적은 재계산 값으로 집계하되, 변경 이력은 지우지 않습니다.
- **처음 기록된 시각:** 거래마다 처음 기록된 시각을 남겨, 나중에 소급해 만든 기록이 아님을 보입니다.
- **진행 중 상태:** 보유 중인 모의 포지션(진입가·손절·목표)과, 신호가 나왔지만 다음 봉이 아직 없는 '진입 예정'을 따로 표시합니다.
- **보관 위치:** `bnf-forward` 브랜치의 `data/bnf-forward.json`. 앱 코드와 분리해 배포를 만들지 않습니다(`vercel.json` deploymentEnabled=false).
