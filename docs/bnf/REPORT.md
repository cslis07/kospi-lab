# BNF형 25일 이격도 역추세 — ETH 선물 백테스트 결과 보고서

> 연구용 결과입니다. 25일 이동평균 이격도를 쓰는 **BNF형** 규칙이며 BNF 본인의 정확한 매매 알고리즘이 아닙니다.
> 실거래 주문·API 키·자동 진입 기능은 없습니다. 규칙과 판정 기준은 결과를 보기 전에 [STRATEGY.md](STRATEGY.md)에 고정했습니다.
> 결과를 본 뒤 규칙을 바꾸거나 다시 돌리지 않았습니다.

## 1. 결론

**사용 부적합입니다.** Binance(1차)와 Bitget(별도) 모두에서 미리 정한 기준을 통과한 구성이 하나도 없습니다.

- OOS(2024-11-01 이후)에서 거래 30회 이상이 나온 구성은 10개입니다(5x·10x 포함).
  - 이 중 평균 R 이 양수인 것은 **1시간봉·전체 국면**과 **4시간봉·전체 국면(Binance만)**뿐입니다.
  - 그나마 PF 가 1.13~1.14 로 기준 1.2 에 못 미칩니다(**우위 미약**).
- 4시간봉·전체 국면은 거래소에 따라 결과가 갈렸습니다. Binance 는 PF 1.14(+0.065R)이지만 Bitget 은 PF 0.96(−0.015R)입니다. 거의 같은 가격인데도 결과가 뒤집힐 만큼 우위가 얇다는 뜻입니다.
- 일봉과 4시간봉 약세장 한정은 OOS 거래가 30회 미만이라 **판단 불가**입니다. 다만 표본 안 성적도 모두 음수입니다.
- 15분봉은 개발 구간(+0.12R)과 OOS 구간(−0.26R)의 부호가 뒤집혔습니다. 개발 구간에서 좋아 보였던 것이 OOS 에서 유지되지 않은 전형적인 경우입니다.
- 비용은 실패 원인이 아닙니다.
  - 평균 손절 거리는 약 4% 이고, 수수료+슬리피지는 거래당 약 0.03~0.04R 입니다.
  - 비용을 빼기 전(그로스) 평균 R 도 15분봉 −0.05R, 일봉 −0.24R 로 음수입니다.
- 낙폭 자체는 작습니다. MTM 최대낙폭은 OOS 2.8~9.7% 입니다. 다만 이는 1회 위험을 0.5% 로 묶었기 때문이고, 우위가 있어서가 아닙니다.

## 3. 결과 (5x)

- 10x 는 손익이 모든 거래에서 **동일**합니다(검증함). 사용 증거금만 절반입니다.
- 이유: 위험예산 0.5% 로 정한 명목가는 최대 자산의 약 32% 였습니다. 이는 5x 증거금 상한(자산 25% × 5 = 125%)보다 훨씬 작아서 레버리지 상한이 한 번도 걸리지 않았습니다.

## 5. 한계

1. **청산가·유지증거금 미모델링.** 예상 청산가나 파산 확률은 만들지 않았습니다.
   - 대신 진입 대비 최대 역행(MAE)만 사실값으로 기록했습니다.
   - 10x 에서 증거금은 명목가의 10% 입니다. 손절 상한 8% 보다 큰 갭이 나면 실제 거래소에서는 결과가 달라질 수 있습니다.
2. **펀딩 근사.** Binance 펀딩 반영 열은 명목가를 공식 mark price 가 아니라 정산 시각 15분봉 시가로 근사했습니다. 그래서 보조 열로만 둡니다.
3. **15분봉 경로 판정.** 15분 안에서 고가·저가 중 무엇이 먼저였는지는 알 수 없습니다.
   - 같은 봉에서 목표가와 손절가가 함께 닿으면 손절로 처리했습니다(보수적).
   - 갭 상승도 목표가로만 체결했습니다.
4. **표본 크기.** 일봉과 4시간봉 약세장은 OOS 표본이 11~26건이라 결론을 낼 수 없습니다.
   - 2021-11 이전 데이터를 쓰면 표본은 늘어납니다. 다만 그건 규격(2021-11-01 시작)을 바꾸는 일이라 하지 않았습니다.
5. **해석 고정.** 규격 문장 중 해석이 갈릴 수 있는 부분은 STRATEGY.md §3 에 정한 대로 처리했습니다.
   - "최근 4개 봉"은 현재 봉을 포함합니다.
   - "직전 일봉 종가 < 직전 200일 SMA"는 D−1 종가와 D−200…D−1 평균을 비교합니다.
   - 다른 해석으로 다시 돌리면 같은 구간을 재평가하는 것이 되므로 하지 않았습니다.
6. **거래소 차이.**
   - 두 거래소의 15분봉은 신호 수가 0~2% 다릅니다(예: 15분 전체 3,176 vs 3,213).
   - 대부분 구성은 결과가 거의 같지만, 4시간·전체는 PF 1.14 vs 0.96 으로 갈렸습니다.
   - Bitget 은 원본 파일 해시가 없는 API 수집이라 정규화 CSV 의 SHA256 만 기록했습니다.
7. **단일 실행.** 매개변수 최적화나 민감도 탐색은 하지 않았습니다. 하지 않은 것 자체가 이 연구의 조건입니다.

## 8. 변경 파일

| 구분 | 경로 |

| 신규 · 계산 | `lib/bnf/data.ts`, `lib/bnf/indicators.ts`, `lib/bnf/engine.ts`, `lib/bnf/metrics.ts`, `lib/bnf/zip.ts`, `lib/bnf/view.ts` |

| 신규 · 결과 | `data/bnf/binance/{manifest.json,results.json,summary.csv,trades.csv,monthly.csv}`, `data/bnf/bitget/(같은 5개)` |
| 신규 · 화면 | `app/bnf-lab/page.tsx`, `app/bnf-lab/layout.tsx`, `components/bnf/BnfLabView.tsx` |
| 신규 · 문서 | `docs/bnf/STRATEGY.md`, `docs/bnf/REPORT.md` |

| 수정 | `.gitignore` — `/.bnf-data/` 원본 캐시 제외 |

변경하지 않은 것:
- 기존 화면·컴포넌트·스타일
- 메뉴(`lib/menu.ts`)·사이트맵
- 분석·복기·수수료·펀딩·손익 로직
- DB 스키마, 배포

**경로를 `/research/bnf` 가 아니라 `/bnf-lab` 으로 둔 이유:**
- `lib/menu.ts` 의 기존 판정은 `/research/…` 하위 경로를 기존 '리서치'(애널리스트 리포트) 메뉴로 봅니다.
- 그래서 `/research/bnf` 를 쓰면 화면 제목이 '리서치'로 뜨고 시장 탭이 강조됩니다.
- 이를 피하려면 기존 메뉴 코드를 고쳐야 합니다. `/event-lab` 과 같은 독립 경로로 두면 메뉴에 연결되지 않습니다.

`/bnf-lab` 의 성격:
- 페이지는 정적으로 렌더링됩니다(빌드 시 JSON 포함). 서버 함수 실행도 외부 API 호출도 없습니다.
- 사이트 전체가 noindex 이고 메뉴·사이트맵에도 없지만, 주소를 알면 누구나 열 수 있는 공개 페이지입니다(앱의 다른 화면과 같은 정책).

## 9. 재현

```
npx tsx scripts/bnf-fetch.ts binance     # 원본 60개월 + 펀딩, CHECKSUM 검증 → .bnf-data/ + manifest

```

## 10. 롤백

이 모듈은 커밋 하나에 담겨 있으므로 `git revert <그 커밋>` 하나로 되돌립니다. 로컬 원본 캐시는 따로 지웁니다(`rm -rf .bnf-data`).
- 변경은 모두 새 파일입니다. 기존 파일 수정은 `package.json` 테스트 스크립트 1줄과 `.gitignore` 2줄뿐이므로, 다른 기능에 영향 없이 되돌릴 수 있습니다.
