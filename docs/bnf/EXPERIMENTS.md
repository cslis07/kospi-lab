# BNF 연구 — 추가 실험 사전등록 (2026-11-03, 결과 보기 전 고정)

1차 연구([STRATEGY.md](STRATEGY.md))의 결론은 '사용 부적합'이었습니다. 아래 추가 실험은 모두 1차 규칙과 판정 기준을 **바꾸지 않고**, 데이터·코인·비용·가설만 바꿉니다.
- 각 실험은 한 번만 실행합니다.
- 결과를 본 뒤 이 문서의 규칙을 고쳐 다시 돌리지 않습니다.
- 1차 실험의 개발(2022-11~2024-10)·OOS(2024-11~) 구간을 다른 규칙으로 다시 맞추는 일도 하지 않습니다. 같은 구간 재평가 금지입니다.

공통 사항:
- 엔진: `lib/bnf/engine.ts` (롱 전용·1포지션·다음 봉 시가 체결·손절 우선·갭 불리 체결·72h 만기·24h 대기)
- 판정: `lib/bnf/metrics.ts verdict` (거래 30회 미만 판단 불가 → PF·평균 R → 낙폭 10% → PF 1.2 → 개발 구간 일관성 → 펀딩 반영)
- 결과 경로: `data/bnf/<실험 ID>/`
- 서로 다른 거래소·코인의 데이터는 한 실험에서 섞지 않습니다.

## E3. 실패 원인 진단 — 모든 실험의 결과에 추가

수익률이 아니라 원인을 봅니다. 아래 정의는 결과를 보기 전에 정했습니다.

- **청산 사유별 성적:** 사유(목표·손절·갭 손절·72h 만기·데이터 끝)별 거래 수와 평균 R
- **MFE(R 단위):** 진입 뒤 청산 전까지의 최고가 기준 `(최고가 − 진입가) / (진입가 − 손절가)`. 구간 `< 0.5R`, `0.5–1R`, `1–1.8R`, `≥ 1.8R` 별 거래 수
- **MAE(R 단위):** 같은 방식으로 최저가 기준
- **+1R 이상 갔다가 손실로 끝난 거래 수:** 되돌림으로 이익을 놓친 거래
- **만기 청산 거래의 평균 R:** 72h 안에 목표·손절 어느 쪽에도 닿지 않은 거래가 얼마나 남겼는지

## E4. 가설 2: 펀딩비 음수 극단 역추세 — `binance-funding`

BNF형 이격도와는 별개의 가설입니다. 같은 엔진·청산·판정을 씁니다.

| 항목 | 내용 |
|---|---|
| 데이터 | 1차 Binance ETHUSDT 15m(2021-11-01 ~ 2026-10-27 23:45 UTC) + 같은 기간 Binance 공식 펀딩비 아카이브 |
| 신호 | 펀딩 정산 시각 `t` 의 실제 펀딩비 `f` 가 **음수**이면서 **직전 365일(t 이전) 정산 펀딩비들의 10% 분위수 이하**일 때. 숏이 몰린 상태로 보고 롱 역추세로 들어갑니다 |
| 분위수 창 | `[t − 365일, t)` 의 정산 건만 씁니다(당일 이후 제외). 1,000건 미만이면 계산하지 않습니다(신호 없음) |
| 확정·체결 | 정산 시각이 속한 15분봉의 **다음** 15분봉 시가 × (1 + 슬리피지) 입니다. 정산 직후에야 값이 확정되므로 같은 봉 시가로 체결하지 않습니다 |
| 국면 | 전체 / 약세장 한정(`close_{D−1} < SMA200(D)`, D = 정산 시각의 UTC 날짜) |
| 청산 | 1차와 같습니다(4h ATR14 × 1.5, 1.2~8%, 1.8R, 72h, 24h 대기, 1포지션) |
| 구간·판정 | 개발 ~2024-10-31 / OOS 2024-11-01~, 1차와 같은 판정. 펀딩 반영 보조 열 포함(이 가설은 롱이 펀딩을 받는 쪽이라 반영 시 유리해질 수 있음 — 그대로 보고) |
| 표시 | 시간봉 대신 '정산 이벤트' 한 종류. 5x·10x 비교는 1차와 같이 둡니다 |

## E5. 실사용 비용 가정 — `binance-cost`, `bitget-cost`

| 항목 | 1차 기본값 | 이 실험 |
|---|---|---|
| 진입 | 수수료 0.05% + 슬리피지 0.02% | **시장가: 테이커 0.06% + 슬리피지 0.05%** |
| 손절·72h 만기·데이터 끝 청산 | 0.05% + 0.02% | **시장가: 테이커 0.06% + 슬리피지 0.05%** |
| 목표 청산 | 0.05% + 0.02% | **지정가: 메이커 0.02%, 슬리피지 0** |

- 이 값은 앱 위험관리 컨트롤 기본값(`lib/riskControl.ts` — taker 0.06·maker 0.02·slippage 0.05)과 같습니다. 개인 계좌 체결 내역은 공개 저장소에 남지 않도록 쓰지 않았습니다.
- 데이터·규칙·구간·판정은 1차(`binance`, `bitget`)와 같고 비용만 바뀝니다.
